# SEO & Google Search Console

> How TemplaFill is made discoverable, and the exact steps to register the site in Google Search Console (GSC).

**Owner**: Both (docs/7-operations) · **Implementation**: `frontend/src/lib/seo.ts` + Next.js metadata file conventions · **Last verified**: 2026-09-27 (local production build)

---

## 1. What Ships

All SEO metadata is generated by Next.js App Router **file conventions** and a single config module, so every value has exactly one source of truth.

| Artifact | Source | Served at |
|----------|--------|-----------|
| Title, description, keywords, canonical | `frontend/src/lib/seo.ts` → `frontend/src/app/layout.tsx` | every page `<head>` |
| `robots.txt` | `frontend/src/app/robots.ts` | `/robots.txt` |
| `sitemap.xml` | `frontend/src/app/sitemap.ts` | `/sitemap.xml` |
| Web app manifest | `frontend/src/app/manifest.ts` | `/manifest.webmanifest` |
| Open Graph image (1200×630 PNG) | `frontend/src/app/opengraph-image.tsx` + `frontend/src/lib/ogImage.tsx` | `/opengraph-image` |
| Twitter/X card image | `frontend/src/app/twitter-image.tsx` | `/twitter-image` |
| JSON-LD structured data (`WebApplication` + `WebSite`) | `frontend/src/components/StructuredData.tsx` | inline in `<body>` |
| Google site-verification meta tag | `layout.tsx` via `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` | every page `<head>` |
| Theme color / color scheme | `viewport` export in `layout.tsx` | every page `<head>` |

### Rendered tags (verified in the production build)

```html
<title>TemplaFill | AI PDF Data Extraction into Word, Excel &amp; PowerPoint Templates</title>
<meta name="description" content="TemplaFill extracts structured data from source PDF documents …" />
<link rel="canonical" href="https://templa-fill.vercel.app" />
<meta name="robots" content="index, follow" />
<meta name="googlebot" content="index, follow, max-video-preview:-1, max-image-preview:large, max-snippet:-1" />
<meta property="og:title" content="…" />
<meta property="og:image" content="https://templa-fill.vercel.app/opengraph-image?<hash>" />
<meta property="og:image:width" content="1200" />
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:image" content="https://templa-fill.vercel.app/twitter-image?<hash>" />
<meta name="google-site-verification" content="<token>" />   <!-- only when configured -->
```

### `robots.txt` (generated)

```
User-Agent: *
Allow: /
Disallow: /api/
Disallow: /uploads/

User-Agent: Googlebot
Allow: /
… (Googlebot-Image, Bingbot, Slurp, DuckDuckBot, Applebot, Baiduspider, YandexBot)

Host: templa-fill.vercel.app
Sitemap: https://templa-fill.vercel.app/sitemap.xml
```

> `/_next/static/*` is intentionally **not** disallowed: Googlebot must fetch CSS/JS to render the page and evaluate metadata.

### `sitemap.xml` (generated)

The app is a single-page workflow (all other states are client-side), so the sitemap lists the landing route only:

```xml
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://templa-fill.vercel.app</loc>
    <lastmod>…</lastmod>
    <changefreq>weekly</changefreq>
    <priority>1</priority>
  </url>
</urlset>
```

## 2. Environment Variables

| Variable | Required | Purpose |
|----------|----------|---------|
| `NEXT_PUBLIC_SITE_URL` | Recommended | Canonical origin used for `canonical`, OG/Twitter URLs, sitemap, and robots `Host`. Default: `https://templa-fill.vercel.app`. **No trailing slash.** Set this on Vercel if the domain changes. |
| `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` | Optional | The `content` value from GSC's **HTML tag** verification method. When set, `<meta name="google-site-verification" …>` is emitted on every page. |

Both are `NEXT_PUBLIC_*` on purpose: the values are public (they appear in the HTML anyway), so they are safe in the browser bundle and require **no backend changes**.

> Do **not** commit a real verification token if you prefer to keep it private — the DNS method (§3 option B) needs no token at all.

## 3. Registering in Google Search Console

### Step 0 — Preconditions (already done in this repo)

- [x] `robots.txt` allows crawling and advertises the sitemap.
- [x] `sitemap.xml` is generated and valid.
- [x] Canonical URL is absolute (`https://templa-fill.vercel.app`).
- [x] Title, description, and Open Graph tags render in the **server HTML** (verify with `Ctrl+U`, not DevTools).
- [x] The site returns `200` without JavaScript for the landing route (statically prerendered).

### Step 1 — Add the property

1. Go to <https://search.google.com/search-console>.
2. Click **Add property**.
3. Choose **URL prefix** and enter `https://templa-fill.vercel.app` (use *Domain* only if you own DNS for a custom domain).

### Step 2 — Verify ownership (pick one)

**Option A — HTML tag (fastest, token via env var)**

1. In GSC, expand **HTML tag** and copy the `content="…"` value.
2. Add it to Vercel: **Project → Settings → Environment Variables** →
   `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION = <token>` (Production, and Preview if desired).
3. Redeploy (Vercel → Deployments → ⋯ → Redeploy).
4. Confirm the tag is live:
   ```bash
   curl -s https://templa-fill.vercel.app | findstr /C:"google-site-verification"
   ```
5. Back in GSC, click **Verify**.

**Option B — DNS TXT record (no token in the repo)**

1. In GSC, expand **Domain name provider** and copy the TXT value.
2. In Cloudflare/Vercel DNS, add `TXT @ google-site-verification=<value>`.
3. Wait for propagation, then click **Verify**. (Works for `https://templa-fill.vercel.app` only if you control that DNS; otherwise use Option A.)

**Option C — Google Analytics / Tag Manager** — only if GA4 is already installed. Not currently part of this repo.

### Step 3 — Submit the sitemap

1. In GSC, select the property → **Sitemaps**.
2. Enter `sitemap.xml` and click **Submit**.
3. Status should read **Success** with 1 discovered URL (processing can take a few hours).

### Step 4 — Request indexing

1. **URL Inspection** → paste `https://templa-fill.vercel.app/` → Enter.
2. Confirm **URL is on Google** / **Page is not indexed** state.
3. Click **Test live URL**, then **Request indexing**.

### Step 5 — Post-registration checks

| Check | Where | Expected |
|-------|-------|----------|
| `robots.txt` fetched | GSC → Settings → robots.txt | `200`, matches §1 |
| Sitemap read | GSC → Sitemaps | Success, 1 URL |
| Rich results | [Rich Results Test](https://search.google.com/test/rich-results) | `WebApplication` + `WebSite` detected |
| Social card | [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/) / [X Card Validator](https://cards-dev.twitter.com/validator) | 1200×630 card renders |
| Core Web Vitals | GSC → Experience | Landing route is statically prerendered (no CLS from fonts — `next/font` self-hosts) |
| Mobile usability | GSC → Experience → Mobile | Passes (responsive at 360 px+) |

> **Render cold start**: the backend sleeps after 15 min idle, but that does **not** affect SEO — the landing route is fully static on Vercel and makes no backend call before user interaction.

## 4. Adding Pages Later

To index a new route:

1. Add the path to `INDEXABLE_ROUTES` in `frontend/src/lib/seo.ts`.
2. Give the page its own `metadata` export (or `generateMetadata`) with a `title` and `description`; the root template appends `| TemplaFill`.
3. Keep exactly one `<h1>` per page (currently the hero headline in `HeroLanding.tsx`).
4. Re-run `npm test` — `src/tests/seo.test.mjs` guards the invariants (S1–S9).

## 5. Guardrails & Tests

`frontend/src/tests/seo.test.mjs` (9 tests, part of `npm test`) fails the build if any of these regress:

- `SITE_URL` is HTTPS with no trailing slash (S1)
- `metadataBase`, canonical, and `googleBot` directives are set (S2)
- The GSC verification env hook exists (S3)
- `robots.ts` allows crawling and disallows `/api/` (S4)
- `sitemap.ts` lists the root route at priority 1 (S5)
- OG/Twitter cards are 1200×630 (S6)
- JSON-LD contains `WebApplication` + `WebSite` nodes (S7)
- Title template, keywords, locale, and Twitter card type are present (S8)
- The manifest has name/start URL/theme color (S9)

Full verification command:

```bash
cd frontend
npm test        # 73/73 (includes SEO S1–S9)
npm run lint
npm run build   # emits /robots.txt, /sitemap.xml, /opengraph-image, /twitter-image, /manifest.webmanifest
```

Inspect the built output without deploying:

```bash
# after npm run build
Get-Content .next/server/app/robots.txt.body
Get-Content .next/server/app/sitemap.xml.body
Get-Content .next/server/app/index.html   # search for <meta name="robots"
```

## 6. Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| GSC says "Couldn't fetch" | Vercel deployment protection enabled | Vercel → Settings → Deployment Protection → allow public access |
| `google-site-verification` missing in HTML | Env var set after deploy | Redeploy; env vars are baked at build time |
| Sitemap shows `https://localhost:3000` | `NEXT_PUBLIC_SITE_URL` unset in the build environment | Set it in Vercel and redeploy |
| "Excluded by noindex tag" | A page-level `robots: { index: false }` exists | Remove it (only the root layout sets robots today) |
| OG image is blank in previews | Crawler cached an older hash | Re-scrape via the Sharing Debugger |
| Duplicate canonical warnings | A second canonical tag injected by an extension | Test with `curl`, not a browser with extensions |
